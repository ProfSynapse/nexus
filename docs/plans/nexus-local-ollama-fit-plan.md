## Summary

Replace the fragile WebLLM-first local-model experience with a curated **Nexus Local** workflow backed by Ollama.

The normal path is deliberately small:

```text
Set up Nexus Local
        ↓
Model:   Nexus Electron — Recommended
Context: Auto — 32K recommended
        ↓
Find best fit
        ↓
Download recommended model
        ↓
Start chatting
```

Nexus owns the product experience: Ollama detection, guided installation, the curated Nexus model catalog, download progress, hardware-fit testing, model/context recommendation, and accurate auto-compaction. Ollama owns inference, hardware backends, model storage, model transfer, and process isolation.

Flash Attention, KV-cache format, memory headroom, GPU placement, prompt speed, and compaction thresholds remain implementation details. They may appear under **Advanced**, but they are not part of the primary setup flow.

## Scope

### In Scope

- A new curated `nexus-local` provider backed by the existing Ollama transport.
- A small setup surface with model, context, **Find best fit**, download, and status.
- Detection of a running Ollama API, an installed-but-stopped binary, and an absent installation.
- Guided official Ollama installation with explicit user consent.
- Ollama minimum-version and capability checks.
- Curated Nexus model downloads from Hugging Face through Ollama's pull API.
- A device-local recommendation for both model and context.
- Post-download load verification and automatic context fallback.
- Accurate context metadata and Ollama auto-compaction integration.
- Download interruption, disk-space, offline, out-of-memory, and unsupported-device handling.
- A separate Advanced section for custom server URL and diagnostics.

### Out of Scope

- Fine-tuning, merging, quantizing, or publishing the Nexus models themselves.
- Downloading GGUF bytes through Nexus instead of Ollama.
- Silently running `curl | sh`, PowerShell installers, `sudo`, or other privileged commands.
- Silently changing server-wide Ollama environment variables on an installation shared with other apps.
- Removing the generic Ollama provider.
- Automatically deleting user-owned models or uninstalling Ollama.
- Local inference on mobile.
- Benchmarking every model by downloading the entire catalog.

## What the Code Does Today

### Nexus/WebLLM

- `NexusProviderModal` manages WebLLM downloads and browser-cache state.
- `WEBLLM_MODELS` currently contains only Nexus Quark, a 1.7B Qwen3 model with a 4K window.
- The established naming convention already defines Quark, Electron, Proton, and Atom.
- WebLLM remains disabled/fragile on supported platform paths and has known Apple Silicon continuation failures.

### Ollama

- `OllamaAdapter` already supports streaming and non-streaming `/api/chat`.
- It supports native Ollama tool calls and the Nexus content-embedded fallback.
- It reports prompt/completion usage and timing from Ollama responses.
- It lists installed models through `/api/tags`.
- `OllamaProviderModal` already supports server URL, connection testing, `num_ctx`, `/api/ps` loaded status, and manual tuning guidance.
- There is no `/api/version`, `/api/pull`, `/api/show`, or managed setup workflow in Nexus today.
- Model selection is split between provider settings and chat/default-model settings.

### Context and Compaction Gaps

- When `num_ctx` is unset, `OllamaAdapter` currently publishes a generous 128K fallback rather than the runtime allocation.
- `/api/ps` already reports the actual loaded `context_length`, but that value is display-only.
- `ModelAgentCompactionState` does not currently create a local context tracker for Ollama.
- `ContextBudgetService` has no Ollama policy, so pre-send auto-compaction can remain disabled.
- The current 90% compaction trigger and 5% reserve are fixed percentages rather than an output/tool-aware budget.
- The compaction frontier has a 900-token minimum, which is disproportionately large for small local windows.

### Reusable Infrastructure

- `resolveDesktopBinaryPath()` can locate executables through PATH, common locations, and login shells.
- `LocalCliInstaller` provides a useful status/plan/install/repair state-machine pattern, although Ollama installation is third-party and must remain separately owned.
- `requestUrl()` is sufficient for the Ollama management API; no new HTTP dependency is needed.
- `app.loadLocalStorage()` / `app.saveLocalStorage()` can keep device-specific fit results out of synced settings.

## Architecture Phase

### Provider Boundary

Add a distinct `nexus-local` provider.

- `nexus-local` exposes only curated Nexus models and the managed setup experience.
- `ollama` remains the advanced/generic provider for arbitrary installed models and custom/remote servers.
- Both use the same battle-tested Ollama generation transport.
- Do not duplicate streaming, tool-call parsing, reasoning, or usage normalization.
- Keep `webllm` readable for legacy settings during the transition; do not silently delete its browser cache or settings.
- Do not automatically migrate an existing WebLLM default until Nexus Local is installed and ready on that device.

### Core Components

| Component | Responsibility |
|-----------|----------------|
| `NexusLocalModelCatalog` | Curated model names, HF/Ollama refs, release metadata, context candidates, download size, measured fit profiles, Nexus eval grade |
| `OllamaManagementClient` | `/api/version`, `/api/tags`, `/api/ps`, `/api/show`, `/api/pull`, preload, unload, and typed error parsing |
| `OllamaRuntimeService` | Probe API first, discover binary second, distinguish missing/stopped/outdated/ready, start only with consent |
| `OllamaInstallCoordinator` | Platform-specific official download/open flow and post-install polling |
| `NexusLocalFitService` | Device snapshot, preflight filtering, optional calibration, context ladder, recommendation, invalidation |
| `NexusLocalDeviceProfileStore` | Device-local recommendation and benchmark cache |
| `NexusLocalProviderModal` | Small UI state machine; no hardware or API business logic |
| Existing `OllamaAdapter` | Generation, streaming, tools, reasoning, and provider usage |

### Model Catalog Contract

```typescript
export type NexusLocalSizeClass = 'quark' | 'electron' | 'proton' | 'atom';

export interface NexusLocalModelSpec {
  id: string;
  displayName: string;
  sizeClass: NexusLocalSizeClass;
  parameterRangeLabel: string;
  ollamaRef: string;
  downloadBytes: number;
  nativeContextLength: number;
  contextCandidates: number[];
  minimumOllamaVersion: string;
  architecture: string;
  quantization: string;
  nexusEval: {
    rawPassRate: number;
    attributedPassRate: number;
    evaluatedAt: string;
    reportArtifact: string;
  };
  fitProfiles: Array<{
    contextLength: number;
    estimatedWorkingSetBytes: number;
    recommendedMemoryBytes: number;
  }>;
}
```

Catalog checks must fail when IDs collide, context candidates exceed the native window, a release lacks an eval artifact, or a model has no fit profile.

### Runtime State Contract

```typescript
export type OllamaRuntimeState =
  | { status: 'probing' }
  | { status: 'missing' }
  | { status: 'installed-stopped'; binaryPath: string }
  | { status: 'outdated'; version: string; minimumVersion: string }
  | { status: 'ready'; version: string; serverUrl: string }
  | { status: 'remote'; version: string; serverUrl: string }
  | { status: 'error'; message: string; recoverable: boolean };
```

Detection order:

1. Probe `GET /api/version` at the configured URL.
2. If localhost does not respond, resolve the `ollama` binary.
3. If the binary exists, report stopped/outdated rather than reinstalling.
4. If it does not exist, offer the official installer.
5. Poll `/api/version` after installation/start until ready or timed out.
6. For non-loopback URLs, never install, start, stop, or inspect the local machine on the server's behalf.

### Recommendation Contract

```typescript
export interface NexusLocalRecommendation {
  modelId: string;
  contextLength: number;
  confidence: 'verified' | 'estimated';
  fit: 'fast' | 'balanced' | 'slow';
  reason: string;
  measured?: {
    loadedContextLength: number;
    sizeBytes: number;
    sizeVramBytes: number;
    promptTokensPerSecond: number;
    generationTokensPerSecond: number;
  };
}
```

Recommendation is lexicographic, not a hidden weighted score:

1. Reject unsupported architecture, Ollama version, disk, or memory profiles.
2. Reject model releases below the Nexus tool-use quality gate.
3. For each remaining model, choose the largest context that meets the balanced latency and headroom gates.
4. Choose the highest-quality model among those balanced profiles.
5. Prefer the smaller/faster profile when two choices are materially equivalent.

The exact gates belong in a versioned fit-policy object and tests, not scattered UI constants.

### Estimated Versus Verified Fit

**Find best fit** must be honest about what has actually been tested.

- Before a model is downloaded, the result is **estimated** from the device snapshot and release fit profiles.
- If a compatible installed model is available, use it for a short calibration and improve the estimate.
- Do not download the whole catalog to benchmark it.
- After the recommended model downloads, preload it at the recommended context, read `/api/ps`, run a short representative prompt, and upgrade the result to **verified**.
- If verification fails, reduce context first. If the model still fails to load, offer the next smaller model; do not silently download it.

### Device-Local Persistence

Hardware results must not sync between devices.

Store in Obsidian local storage under a versioned key:

```typescript
export interface NexusLocalDeviceProfile {
  schemaVersion: number;
  hardwareFingerprint: string;
  ollamaVersion: string;
  catalogVersion: string;
  testedAt: number;
  recommendation: NexusLocalRecommendation;
}
```

Invalidate when the hardware fingerprint, Ollama version, catalog version, selected model build, or fit-policy version changes. Installed model state is always rediscovered from Ollama and is never trusted from persistence.

### Context Source of Truth

Keep these values distinct:

```text
model native maximum
        ≠
requested context
        ≠
actual loaded context
```

The actual loaded context from `/api/ps` is the operating budget after load. The explicit configured/recommended value is the conservative pre-load budget. Never publish 128K merely because the true value is unknown.

### Auto-Compaction Integration

The local recommendation is incomplete unless compaction uses the same context value.

```text
actual loaded context
  - fixed system/tool prompt
  - active compaction frontier
  - reserved output
  - tool-continuation reserve
  - safety margin
  = live conversation budget
```

Required behavior:

- Add `nexus-local` and generic `ollama` to provider-aware context budgeting.
- Reconcile estimates with Ollama's `prompt_eval_count` after every response.
- Reserve enough output for a response plus a tool-result continuation; do not rely on a flat 5% reserve.
- Trigger before exhaustion, then compact back below a lower target to avoid compacting every turn.
- Scale the frontier budget to the actual local context; remove the 900-token floor for very small windows.
- Keep raw transcript JSONL as source of truth and use the existing compaction frontier/recovery services.
- Preserve Auto context as a concrete resolved token value for the current device, not an ambiguous server default.

### Ollama Tuning Boundary

- Send context per request with `num_ctx`.
- Let current Ollama use Flash Attention automatically when supported.
- Treat q8/q4 KV-cache settings and parallelism as server-wide settings.
- Do not silently mutate an existing user-owned Ollama service.
- In v1, fit-test the server configuration that is actually running.
- Advanced diagnostics may explain how a user can optimize a shared server.
- A future explicitly Nexus-owned runtime profile may manage q8 KV and single-request parallelism, but it is not required for v1.

## Security and Ownership Requirements

- Only manage installation/start behavior for loopback Ollama URLs.
- Validate installer/download URLs against an explicit official allowlist.
- Prefer official signed installers and verify published hashes where available.
- Ask before downloading/opening an installer or starting an installed service.
- Never execute remote install scripts through a shell.
- Never request `sudo` or administrator credentials inside Nexus.
- Never interpolate user input into a shell command.
- Never stop, upgrade, or reconfigure a running user-owned Ollama instance without explicit consent.
- Never send hardware or benchmark telemetry off-device.
- Treat model download sizes and disk-space checks as user-facing requirements.
- Cancellation must leave a recoverable Ollama pull state and a retry action.

## Acceptance Criteria

### Product

- A new user can reach a ready Nexus Local model without opening a terminal.
- The primary surface contains only runtime status, model, context, **Find best fit**, and the current action.
- The catalog uses Quark/Electron/Proton/Atom consistently.
- **Find best fit** recommends both model and context.
- The result clearly distinguishes estimated from verified without exposing tuning jargon.
- Download happens through Ollama with progress, cancellation, and recovery.
- Generic Ollama remains usable.

### Reliability

- Nexus never claims more context than it requested or observed.
- Post-download verification detects load failure, context mismatch, and harmful CPU spill.
- Auto-compaction activates for Nexus Local before the actual runtime limit.
- A failed fit test or download always leaves a visible retry/recovery action.
- Existing user-owned Ollama installations are not silently reconfigured.
- Hardware recommendations remain device-local.

### Engineering

- No duplicated Ollama streaming/tool-call implementation.
- No new runtime dependency is required.
- No desktop-only import becomes reachable from mobile startup.
- Catalog, fit policy, runtime states, and compaction integration have P0 unit coverage.
- The accepted mockup is cited as the visual contract before production UI work starts.
- `npm run lint`, `npm run build`, the focused Jest lane, mobile reachability, and live Ollama verification pass.

## Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| A pre-download estimate cannot prove real inference behavior | Label it estimated; verify immediately after download and adjust context |
| Testing every model would create huge downloads | Use catalog fit profiles and calibrate only installed/recommended models |
| Ollama service settings are global | Test the active configuration; keep server-wide tuning advanced and consent-based |
| Hardware detection differs by OS/backend | Prefer Ollama-observed load behavior over OS guesses; use conservative fallback |
| Model native context differs from useful context | Catalog only eval-tested context candidates; do not extrapolate beyond them |
| Synced settings carry a bad recommendation to another device | Store fit result and resolved Auto context in device-local storage |
| Generic Ollama users lose flexibility | Keep the generic provider separate and unchanged |
| WebLLM migration deletes user data | Make migration explicit; never delete cache automatically |
| Local subagents multiply context memory | Balanced policy assumes serialized local generation; document concurrency as advanced |
