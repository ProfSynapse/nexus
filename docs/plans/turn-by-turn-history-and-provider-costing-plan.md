## Summary

Two related defects in the chat → LLM pipeline, fixed together because the second is
only measurable once the first lands.

**A. Conversation history is flattened into the system prompt.** Every provider except
Google receives its prior turns as a `=== Conversation History ===` text transcript
appended to the system prompt, plus the latest user message as the only real turn. The
provider-specific builders under `src/services/chat/builders/` already produce correct
turn-by-turn history (`tool_use`/`tool_result` blocks, `tool_calls`/`role: tool`,
`functionCall`/`functionResponse`, signed thinking blocks) — two later layers throw that
away. This defeats prompt caching (the system prompt changes every turn), loses tool
arguments and thinking across user turns, and double-sends history on tool
continuations.

**B. Costing ignores cache reads/writes and guesses discounts by model-name prefix.**
`TokenUsage` carries a single `cachedTokens`, no adapter except OpenAI-compat extracts it,
`ModelSpec` has no cache rates, and `LLMCostCalculator.getCachingDiscount` has a dead
branch (`gpt-5.2` can never match because `gpt-5` matches first). Where a provider
reports a price directly (OpenRouter) we only use it via a second HTTP call. Nothing
requests Anthropic prompt caching (`cache_control` appears nowhere in `src/`).

This plan is Phase 4 of `canonical-message-pipeline-plan.md` in spirit but deliberately
**not** Option C (single canonical type with builders as the only converter). Option C
rewrites every provider's continuation path, which works today. The turn-by-turn bug
lives in exactly two functions. Fix those, pin them with unit and live tests, and leave
Option C as its own follow-up.

## What The Code Does Today

### Initial request of every turn (the bug)

```
StreamingResponseService.buildLLMMessages
  ├─ google: hand-rolled {role, content} text-only loop      ← tool history dropped
  └─ others: ConversationContextBuilder.buildContextForProvider (correct)
             .map(m => ({ role, content: typeof m.content === 'string' ? m.content : '' , ...}))
                                                              ← Anthropic content-block arrays → ''
LLMService.generateResponseStream (pass-through, post Phase 3)
StreamingOrchestrator.generateResponseStream
  └─ ProviderMessageBuilder.buildInitialOptions
       ├─ google: rebuilds {role, parts} text-only from content
       └─ others: systemPrompt = system + "=== Conversation History ===\n" + buildConversationHistory(prev)
                  prompt       = last user message
                  conversationHistory = (unset)                  ← text transcript, one real turn
```

`buildConversationHistory` (ProviderMessageBuilder.ts:164) renders assistant tool turns
as `Assistant: [Calling tools: useTools]` — arguments gone — and results as
`Tool Result: {...}`.

### Tool continuation within a turn (works, but inherits the bloat)

`ToolContinuationService` → `buildContinuationOptions` → per-provider
`buildToolContinuation` / `appendToolExecution`. These produce real turns. But they
spread `...generateOptions`, so `systemPrompt` still contains the text transcript. The
model sees history twice on every continuation.

### Adapters already accept structured history

Every non-CLI adapter honours `options.conversationHistory` on the initial request:
Anthropic uses it verbatim as `messages`; Google as `contents`; chat-completions
adapters via `buildMessagesWithConversationHistory`; OpenAI Responses as `input`
(currently only fed `function_call_output` items on continuation, never message items).
The two CLI transports (`anthropic-claude-code`, `google-gemini-cli`) do not — they take
a prompt string and a system prompt, and own their own session state.

### Costing

- `TokenUsage` (adapters/types.ts): `promptTokens`, `completionTokens`, `totalTokens`,
  `cachedTokens?`, `reasoningTokens?`, `audioTokens?`.
- `NormalizedTokenUsage` (ContextBudgetService) and `UsageData` (CostTrackingService)
  and `MessageUsage` (ChatTypes) are all three-field — cache counts are dropped before
  cost is computed in `StreamingResponseService`.
- `AnthropicUsage` (AnthropicAdapter.ts:28) declares only `input_tokens`/`output_tokens`.
  `cache_read_input_tokens` / `cache_creation_input_tokens` are never read.
- `ModelSpec` (modelTypes.ts) has `inputCostPerMillion` / `outputCostPerMillion` only.
- `LLMCostCalculator.getCachingDiscount(model)` guesses by prefix; prefix order bug.
- OpenRouter: `usage: { include: true }` is sent, but cost is taken from a follow-up
  `/generation` fetch (`fetchAndNotifyUsage`) with exponential backoff, not from the
  inline `usage.cost` on the final stream chunk.
- No adapter sends `cache_control`, so Anthropic never caches the system prompt.

## Design Rules

1. **History is turns, not prose.** For any provider whose adapter accepts
   `conversationHistory`, the initial request carries the full prior conversation as
   structured turns and the system prompt carries only instructions, context and the
   compaction frontier. The text-transcript fallback survives in exactly one place, for
   the CLI transports only, behind an explicit allow-list.
2. **The builders' output is the contract.** `buildLLMMessages` returns what the
   provider builder produced, unmodified. No `.map()` that can drop a field. If a field
   needs preserving, it is preserved because nothing touches it.
3. **Compaction frontier stays in the system prompt.** It is designed as a stable
   prefix (`context-compaction-engineering-plan.md`). Only messages after the boundary
   become turns; that filter is unchanged.
4. **Provider-reported price wins.** If the response carries a cost (OpenRouter inline
   `usage.cost`), that is the cost. Otherwise compute from token classes × per-model
   rates, where the rates include cache read and cache write. Prefix-guessing is deleted.
5. **Usage is carried whole.** One `TokenUsage` shape from adapter to persisted message,
   with optional cache-read, cache-write, reasoning and provider-cost fields. No
   intermediate three-field copy.
6. **Ask for the cache.** Anthropic gets `cache_control: { type: 'ephemeral' }` on the
   system block and on the last tool definition. This is what makes rule 1 pay off and
   what makes the cache-read counter in rule 5 observable.

## Step-By-Step Plan

### Workstream A — turn-by-turn history

**A1. Widen `ConversationMessage`** (ProviderMessageBuilder.ts:26).
`content: string | LLMContentBlock[]`, add `parts?: GooglePart[]`. Export a
`getMessageText(msg)` helper that returns the string form (string content, joined
`text` blocks, or joined `parts[].text`) for the two places that need prose: the
`userPrompt` extraction and the CLI fallback.

**A2. `StreamingResponseService.buildLLMMessages`** returns the builder output as-is.
Delete the Google special case (GoogleContextBuilder is used like every other builder)
and delete the `.map()`. The append-user-message fallback at the bottom of
`generateResponse` pushes the shape the builder expects (`parts` for Google).

**A3. `ProviderMessageBuilder.buildInitialOptions`** — one branch per shape:
- `TEXT_HISTORY_PROVIDERS = new Set(['anthropic-claude-code', 'google-gemini-cli'])`
  keep today's behaviour (system + transcript, last message as prompt). This is the
  only remaining caller of `buildConversationHistory`.
- `openai` and `openai-codex`: `conversationHistory = toResponsesInputItems(prev)`,
  where `toResponsesInputItems` is the message→input-item conversion extracted from
  the Codex continuation branch (lines 245–330) into `shared/OpenAIResponsesInput.ts`
  and reused by both. Message items become `{ type: 'message', role, content }`,
  assistant tool calls `function_call`, tool messages `function_call_output`.
  OpenAI's adapter appends the current prompt when `conversationHistory` is present —
  verify, and if it does not, include the last user message as the final item and pass
  `''` as prompt (same as Google).
- everything else: `conversationHistory = nonSystemMessages`, `systemPrompt =
  extractedSystemPrompt`. The adapter appends the prompt or the last message is
  included — check per adapter family (Anthropic: history is verbatim `messages`, so
  the last user message must be in it and prompt is ignored; chat-completions: same
  via `buildMessagesWithConversationHistory`).

**A4. Continuations stop re-sending the transcript.** With A3 the `systemPrompt` in
`generateOptions` no longer contains history, so `buildContinuationOptions` needs no
change beyond OpenAI/Codex sharing the extracted helper.

**A5. OpenAI Responses adapter**: when `conversationHistory` holds message items (not
just outputs) and no `previousResponseId` is set, send them as `input`. Continuations
keep `previous_response_id` + `function_call_output` (stateful within a turn).

**A6. Anthropic `cache_control`.** In `AnthropicAdapter` send `system` as
`[{ type: 'text', text, cache_control: { type: 'ephemeral' } }]` and mark the last tool
definition. Minimum cacheable prefix is 1024 tokens on most models; below that the
provider silently ignores it, which is fine.

**A7. Delete** `buildConversationHistory`'s general use; keep it for the CLI set with a
comment naming why.

### Workstream B — provider-reported costing

**B1. One usage shape.** Extend `TokenUsage` with `cacheReadTokens?`,
`cacheWriteTokens?`, `providerCost?: { totalCost: number; currency: string }`. Keep
`cachedTokens` as a deprecated alias populated equal to `cacheReadTokens`. Make
`NormalizedTokenUsage`, `UsageData` and `MessageUsage` structurally the same type
(re-export), and have `ContextBudgetService.normalizeUsage` and
`CostTrackingService.extractUsage` carry the optional fields through.

**B2. Adapters extract cache counts.**
- Anthropic: `cache_read_input_tokens`, `cache_creation_input_tokens` from
  `message_start` usage (and `message_delta` if present). Note Anthropic's
  `input_tokens` excludes cached tokens — `promptTokens` must be the sum of all three
  input classes so context accounting stays right.
- OpenAI Responses: `input_tokens_details.cached_tokens`.
- Chat-completions family (OpenRouter, Requesty, Groq, Mistral, etc.):
  `prompt_tokens_details.cached_tokens` (TokenUsageExtractor already does this — verify
  it is on the streaming path).
- OpenRouter: inline `usage.cost` and `usage.cost_details.upstream_inference_cost` on
  the final chunk → `providerCost`. Keep the `/generation` fetch only as fallback when
  the inline field is absent.
- Google: `usageMetadata.cachedContentTokenCount`.

**B3. Rates per model.** `ModelSpec` gains `cacheReadCostPerMillion?` and
`cacheWriteCostPerMillion?`. Populate for Anthropic (read = 0.1× input, 5-minute write
= 1.25× input), OpenAI (read per model, no write charge), Google (read per model,
storage not modelled). `ModelRegistry.getModelPricing` exposes them.

**B4. Calculator.** `LLMCostCalculator.calculateCost` computes
`fresh × input + read × cacheRead + write × cacheWrite + output × output`, where a
missing cache rate falls back to the input rate (i.e. no discount, never a guess).
`getCachingDiscount` is deleted. `CostDetails` gains `cacheRead`/`cacheWrite`
breakdowns. If `usage.providerCost` is present it is used for `totalCost` and the
breakdown is informational.

**B5. `CostTrackingService`** passes the full usage through instead of re-projecting to
three fields.

### Tests

**Unit (must fail before, pass after):**
- `tests/unit/ProviderMessageBuilder.initialHistory.test.ts` — for anthropic, google,
  openrouter, openai, openai-codex: given a stored conversation with a prior tool turn,
  `buildInitialOptions` yields `conversationHistory` with the tool turn structured
  (tool_use/tool_result, functionCall/functionResponse, tool_calls/role tool,
  function_call/function_call_output) and `systemPrompt` without
  `=== Conversation History ===`. For `anthropic-claude-code` it yields the transcript.
- `tests/unit/StreamingResponseService.buildLLMMessages.test.ts` — Anthropic content
  block arrays survive; Google gets `parts` with `functionCall`.
- `tests/unit/LLMCostCalculator.cacheRates.test.ts` — four-class arithmetic, alias
  behaviour, provider-cost precedence, and a regression for the `gpt-5.2` prefix bug.
- `tests/unit/AnthropicAdapter.usage.test.ts` — parses a `message_start` with cache
  fields into `TokenUsage`; request body carries `cache_control`.
- Existing: `CanonicalMessagePipeline.phase3`, `AnthropicThinkingContinuation`,
  `azure-call-id-reproduction`, `ProviderMessageBuilder.codex`,
  `StreamingResponseService.compactionBoundary` must stay green.

**Live (gated, `tests/debug/`, user-approved to spend):**
- `tests/debug/turn-history-live-smoke.test.ts`, gate `RUN_TURN_HISTORY_SMOKE=1`.
  For each provider with a key in `.env` (anthropic, openai, google, openrouter):
  1. Turn 1: user asks the model to call a stub tool; execute; complete the turn.
  2. Turn 2: user asks "what did the tool return?" — assert the answer contains the
     stub's distinctive value, proving the tool result reached the model as a turn.
  3. Capture the outbound request body: assert no `Conversation History` in the
     system/instructions and that the prior tool turn is present structurally.
  4. Anthropic only: turn 2 usage has `cacheReadTokens > 0` (system prompt padded past
     1024 tokens), proving A6 + B2 together.
- Existing `provider-model-live-smoke` runs unchanged as the regression check.

## Edge Cases

- **Empty assistant content with tool calls (Anthropic).** Builder already omits the
  text block when content is blank; the message is `[thinking?, tool_use...]`. Anthropic
  rejects an empty *string* content, never an empty text block, and the builder never
  emits one.
- **Consecutive same-role turns.** Anthropic merges them server-side; Google does not
  (`endsWithClientTurn` guard already handles the continuation case; the initial path
  is builder-generated and alternates by construction).
- **Retry (`excludeFromMessageId`)** slices the stored conversation before building —
  unchanged.
- **Compaction boundary** filters before building — unchanged; the frontier text stays
  in the system prompt.
- **Branches / subagents** pass a system message inside `messages`;
  `extractSystemPrompt` still lifts it out.
- **OpenAI Responses stateful ids** are per-turn today (only set on continuation). With
  full history in `input` on every initial request, cross-turn `previous_response_id`
  is unnecessary; do not add it.
- **Custom-format (WebLLM / Nexus SFT) models** already get text-embedded tool calls
  from `CustomFormatContextBuilder`; they flow through the generic branch unchanged.
- **Anthropic `input_tokens` semantics.** Excludes cache read/write tokens. Context
  budgeting must use the sum or the badge under-reports by the cached prefix.
- **Models below the cache minimum** (1024 tokens for most Claude models): the
  `cache_control` marker is ignored, `cacheReadTokens` stays 0, cost is unchanged.

### Bugs the lane found that no mock did

1. **Gemini 3.x: unsigned `functionCall` replay → HTTP 400.** The adapter captured
   the signature as `thought_signature`; `GoogleContextBuilder.toReasoningToolCalls`
   read only the older `thoughtSignature`. Every direct-Google tool continuation
   (turn 1's own follow-up, not just cross-turn history) was failing. Fixed at the
   source; field typed on `LLMToolCall` and `ChatTypes.ToolCall`; pinned by
   `tests/unit/GoogleContextBuilder.thoughtSignature.test.ts`.
2. **Gemini flash tiers reject `role: 'function'`.** `buildContext` replayed stored
   tool results with the legacy role; 3.1 Pro tolerates it, 3.7 Flash and 3.5
   Flash-Lite return 400 `Role 'function' is not supported`. Now a `user` turn
   everywhere (builder, `toGoogleMessage`, `ToolExecutionUtils`), same as the in-turn
   continuation always sent. Pinned in the same test file.
3. **OpenRouter usage never reached the turn.** With `usage: { include: true }` the
   usage frame arrives *after* `finish_reason`; the SSE processors completed at
   `finish_reason` and dropped it, leaving tokens and price to a separate async GET
   that the orchestrator path never wires. New `usageArrivesAfterFinish` option on
   the processors (OpenRouter opts in) completes on `[DONE]` / end-of-stream with
   the usage attached. Pinned in `tests/unit/OpenRouterAdapter.test.ts`.
4. **OpenRouter BYOK reports `cost: 0`.** On a bring-your-own-key request the real
   price is `cost_details.upstream_inference_cost` (`is_byok: true`); the
   normalizer now falls back to it. Also reads `prompt_tokens_details.cache_write_tokens`
   and DeepSeek's `prompt_cache_hit_tokens`.

### Costing improvements made on the way

- OpenAI Responses usage was hand-mapped to three fields, hiding
  `input_tokens_details.cached_tokens` (5328 of 5331 tokens on turn 2 were cache
  reads, billed at 10%) and `reasoning_tokens`. Now normalized.
- Anthropic via OpenRouter cached nothing (no breakpoint). The adapter now marks the
  system message with `cache_control` for `anthropic/*` models only; turn 2 reads
  5915 tokens from cache, cost per turn ≈ 6× lower.
- All non-streaming `extractUsage` overrides (Anthropic, Groq, Mistral, Requesty,
  DeepSeek) go through `TokenUsageExtractor.normalize` — one place knows field names.
