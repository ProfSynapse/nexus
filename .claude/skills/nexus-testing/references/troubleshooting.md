# Troubleshooting: symptom → cause

Each entry is a real failure someone has already spent an afternoon on. Match
the symptom, then act.

## "I fixed the docs and the guidance gate still fails."

You regenerated the tool catalog to the generator's default location under
`docs/generated/`. `tests/unit/shippedGuidanceCommands.test.ts` reads the
repo-root `cli-first-tool-schemas.json`. Re-run with
`--output cli-first-tool-schemas.json`, or run
`scripts/check_catalog_target.py`, which detects exactly this. Full procedure:
`../protocols/fix-shipped-docs-drift.md`.

## "My change to `cliAssets.ts` disappeared."

`src/utils/cliAssets.ts` is generated by `scripts/generate-cli-content.mjs`
during the build, which embeds the built CLI bundle and the guidance sources.
Nothing hand-written survives there. Edit the source guidance instead.

## "The guidance gate and the CLI-syntax test both went red at once."

That is one cause, not two. `tests/unit/ToolManagerCliSyntax.test.ts` pins the
catalog against the live registry precisely so a stale snapshot cannot make the
guidance check vacuous. Fix the catalog once and both clear.

## "The eval model looped `getTools` forever."

A *scenario-scripted* mock is selector-insensitive. `registerStaticResponse` in
`tests/eval/EvalToolExecutor.ts` builds a handler that discards its arguments
and returns the same blob for every call, so a scenario that exposes only some
agents makes the model conclude discovery is broken and retry. Expose every
agent the scenario could plausibly need.

Only the scripted path is blind. With no scripted mock, discovery does filter by
the requested selectors — do not misdiagnose the auto-generated path this way.

## "Ranking looks right locally and wrong in the vault."

The fuzzy-search mock in `tests/mocks/obsidian/core.ts` charges a **bounded**
per-discontiguity penalty, and the bound is what reproduces the original bug —
it keeps `1 + score/100` landing just under 1.0. Making the penalty proportional
feels more faithful and makes the tests vacuous: they stop distinguishing the
tiers at all.

## "I added a scoring rule and everything still passes."

Read the tier constants in `src/agents/searchManager/tools/searchContent.ts`
before adding one. The ladder is a **single scale**. The original defect was a
second, incommensurable scale for filename fuzzy matching, which let a
coincidental filename outrank a verbatim body match. Any new score has to be
placed on the existing ladder, not beside it.

## "My filename normalisation broke snippet offsets."

Separator folding (`foldSeparators`) is applied to **both sides of the filename
comparison only**. Note bodies stay byte-exact so snippet offsets keep pointing
at real text. If you folded a body, that is the bug.

## "The live test ran in CI."

Its gate is missing or inverted. A live lane is inert only because the file
selects `describe.skip` when its env var is unset — `npm run test` collects
every lane. Run `scripts/check_live_lane_gates.py`.

## "A live lane skipped even though I set the gate."

Several lanes need more than the gate: a provider key, a fixture path, or a
vault name. Read the file's header and list its variables with
`grep -oE 'process\.env\.[A-Z_]+' <file>`.

## "`plugin:reload` didn't pick up my fix."

Either the build did not succeed in the same run, or the change lives in state
that outlives the plugin instance. Walk the escalation ladder in
`../protocols/live-loop.md` step 4 rather than editing again.

## "A clean `dev:mobile` run means it is mobile-safe."

It does not. `dev:mobile` emulates the mobile environment, not the absence of
Node built-ins — `require('fs')` still resolves under Electron. The mobile
failure class is `nexus-mobile-compat`'s territory.
